# Data And Storage

This document defines authoritative storage, rebuild boundaries and retention
expectations. It intentionally does not list every table; schema details are in
`src/wikipediarag/db.py`.

## Authoritative Storage Matrix

| Storage | Data | Source of truth | Rebuildable | Retention | Backup requirement | Failure impact |
| --- | --- | --- | --- | --- | --- | --- |
| PostgreSQL | Tenants, users, identities, sessions, groups, grants, audit events, KBs, `knowledge_sources`, `source_sync_runs`, `source_document_states`, upload sessions/batches, jobs/items, documents, versions, artifact metadata, chunks, document sections, index versions, `query_runs`, `retrieval_events`, `agent_runs` | Yes for control plane, lifecycle, chunk metadata/navigation and recovery state | No, except some data can be reseeded in local dev | Per configured DB retention and document lifecycle | Consistent DB dump | API/worker cannot operate; auth, jobs and retrieval metadata unavailable |
| MinIO | Original uploads, normalized documents, parser reports and other object artifacts | Yes for object bytes/artifacts | No for original uploads; normalized/parser artifacts may be regenerated by reprocess if originals remain | Document lifecycle and object-storage policy | Bucket mirror/export with DB-consistent point | Uploads, parsing, reprocess and purge fail |
| OpenSearch | BM25/vector search documents with tenant and KB fields | No | Yes from PostgreSQL chunks/artifacts and index versions | Derived index lifecycle | Optional; rebuild preferred | Retrieval fails or is stale; source-of-truth data remains in PostgreSQL/MinIO |
| Redis/Valkey | Not confirmed from the current implementation | No | Yes | Transient only | None confirmed | Not confirmed from the current implementation; API `/ready` does not check it |
| Kiwix/ZIM | Read-only Wikipedia source archive | Source snapshot for Wikipedia import | Imported index can be rebuilt if same ZIM snapshot remains | Operator-managed local ignored files | Preserve required ZIM snapshots if rebuild is needed | Wikipedia import/source viewing fails |
| Browser memory | UI state, selected files before upload, answers and progress | No | Yes by reload and API polling | Page lifetime | None | User loses in-progress UI state |
| `artifacts/` | Eval, validation and smoke reports | Evidence artifacts only | Usually no; reruns create new immutable reports | Operator-managed ignored artifacts | Preserve important reports externally if needed | Historical validation evidence unavailable |

## PostgreSQL

PostgreSQL is the control-plane source of truth. It stores:

- tenants, users, tenant memberships and platform roles;
- auth identities, OIDC flows, auth sessions and hashed session/CSRF tokens;
- local/OIDC groups and group memberships;
- knowledge bases, `knowledge_sources`, `source_sync_runs`,
  `source_document_states` and KB grants;
- audit events;
- upload batches, upload sessions, ingestion jobs and ingestion job items;
- documents, document versions and document artifact metadata;
- chunks, document sections, publication status and index versions;
- `query_runs`, `retrieval_events` and `agent_runs`.

Current `agent_runs` rows store completed Extended Search harness state and
budgets as a ledger attached to a query run. They are not yet a resumable Deep
Research run lifecycle, and there are no separate typed evidence memory or
coverage record tables.

Lifecycle states include job `received`, `running`, `completed`, `failed` and
`cancelled`; document/version states such as `active`, `deleting`,
`purge_failed` and `deleted`; chunk `publication_status` such as `staged`,
`published` and `deleted`.

PostgreSQL is required for recovery because it links tenants, KBs, documents,
object keys, lifecycle state, chunk metadata, active index aliases and query
events. It stores chunk text/metadata and embeddings used for local dense scan
fallback, so it is more than metadata-only for chunks.

## MinIO

MinIO stores object bytes:

- original uploads under server-generated `uploads/{tenant_id}/{kb_id}/...` paths;
- batch uploads under `uploads/{tenant_id}/{kb_id}/batches/{batch_id}/...`;
- normalized documents under `documents/{tenant_id}/{document_id}/{document_version_id}/normalized.json`;
- parser reports under `documents/{tenant_id}/{document_id}/{document_version_id}/parser-report.json`.

Object keys are generated server-side and recorded in PostgreSQL. Browser batch
status does not expose object keys. Parser services receive bytes/temp files
over HTTP; they do not receive MinIO credentials or object keys.

Soft delete marks documents and chunks out of retrieval immediately. Deferred
purge deletes MinIO artifacts after retention and then marks lifecycle state.
Backups must preserve MinIO consistently with PostgreSQL.

## OpenSearch

OpenSearch stores derived search documents for BM25 and vector search. Search
documents carry `tenant_id`, `knowledge_base_id`, `document_id`, `chunk_id`,
text fields, embedding, source URL and metadata.

OpenSearch is not authoritative. Worker publication writes chunks to
PostgreSQL, bulk indexes published chunks into OpenSearch, validates count, then
updates DB chunks/version to published. Deletion removes derived OpenSearch
chunks by `tenant_id + knowledge_base_id + document_id`.

Retrieval applies server-owned tenant and KB filters for BM25 and dense search.
Active KB index compatibility is checked before retrieval; incompatible or
missing indexes fail safely with `KB_NOT_READY`.

Rebuild requires PostgreSQL chunk/index metadata plus MinIO artifacts where
reprocessing is needed.

## Redis Or Valkey

Redis/Valkey is present in Compose and settings, but no Redis client usage was
found in `src/`. Current ingestion queue and item claiming use PostgreSQL rows
and `FOR UPDATE SKIP LOCKED`.

Do not treat Redis/Valkey as durable state. Not confirmed from the current
implementation.

## Kiwix And ZIM

Kiwix serves local ignored ZIM files read-only. The ZIM snapshot is the source
archive for Wikipedia import. Imported chunks and OpenSearch indices are tied
to source snapshot and retrieval/index contract metadata. If the same ZIM is
not preserved, an exact Wikipedia rebuild may not be possible.

## Document Lifecycle

1. Upload session or batch session records are created in PostgreSQL.
2. Browser uploads bytes directly to MinIO using a presigned URL.
3. Completion creates document, version, original artifact metadata, job and job item rows.
4. Worker validates bytes, parses and normalizes content.
5. Worker writes normalized JSON and parser report to MinIO and records artifact metadata.
6. Worker chunks and embeds content, stages chunks in PostgreSQL, indexes published chunks to OpenSearch, writes document sections and publishes DB state.
7. Failed or cancelled jobs do not publish searchable chunks.

## Soft Delete And Purge

`DELETE /api/v1/documents/{document_id}` requires KB `OWNER`. It marks the
document/version lifecycle as `deleting`, marks DB chunks deleted, deletes
OpenSearch chunks immediately and schedules a `document_delete` job for
`purge_after`. After the retention window, worker purge deletes MinIO artifacts,
DB chunks and artifact rows, then marks lifecycle `deleted` or `purge_failed`
with a safe error code.

Default retention is `DOCUMENT_SOFT_DELETE_RETENTION_DAYS=30`.

## Reprocessing And Reindexing

Reprocess enqueues a document upload job for the current version. Reindexing
uses versioned index contracts and active KB index metadata. OpenSearch can be
rebuilt from durable DB/object state; it should not be the authoritative
backup.

## Sensitive Data

PII and sensitive operational data include usernames, email profile metadata,
session identifiers, provider tokens, uploaded document contents and query
inputs. Local passwords are stored only as Argon2id hashes. App session and
CSRF tokens are stored only as SHA-256 hashes. OIDC provider tokens are stored
encrypted server-side.

Normal logs, public API payloads and validation reports must not include:

- secrets or mounted secret values;
- raw provider tokens or provider payloads;
- prompts;
- raw document contents outside explicit answer/citation payloads;
- MinIO object keys or `s3://` URIs;
- parser stderr or tracebacks;
- cross-tenant data from another actor scope.
