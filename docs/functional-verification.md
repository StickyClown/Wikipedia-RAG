# Сквозная проверка предметных изменений

Проверка выбирается по изменённому договору, а не по количеству затронутых
файлов. Обычный прогон использует только местный имитационный поставщик моделей.
Внешние поставщики и платные вызовы в него не входят.

| Область | Путь через программный вход | Путь через экран | Модель |
| --- | --- | --- | --- |
| вход и разграничение | обязателен для изменённой границы | только важные действия | не нужна |
| загрузка и обработка | загрузка → работник → публикация | загрузка при изменении экрана | только имитационная |
| поиск | обязателен | обязателен | только имитационная |
| ответ и источники | при изменении ответа | для видимого ответа | только имитационная |
| шлюз моделей | настоящий клиент → шлюз → имитационный поставщик | обычно не нужен | внешние вызовы запрещены |
| глубокое исследование | существующие выборочные проверки | один важный путь | только имитационная в обычном прогоне |

Для поиска PostgreSQL — исполняемый владелец решения о публикации, состоянии
документа и доступе. OpenSearch и Redis могут ускорять выбор кандидатов, но
перед выдачей результат повторно подтверждается в PostgreSQL.

AUTH-003 / ING-003 additionally requires the live corrupted-projection case:
the test-owned chunk is canonically `staged` while a realistic OpenSearch
record remains `published`. The record must rank in direct BM25 and dense
candidate paths but be absent from public Search, retrieval debug, and the
Playwright Search UI. Historical discovery, repair, and retention use only
bounded PostgreSQL batches; the normal functional commands remain mock-only.

Локальные команды: `make test-functional-retrieval` и
`make test-functional-ui`. При отсутствии готовой среды обязательный режим
завершается ошибкой с причиной `BLOCKED`, а не успешным пропуском.
